# 海外订阅收录计划

> 更新：2026-10-26 · 对应插件版本 2.34.0

## 目标

1. 收录海外主流订阅制产品，用户一键添加。
2. 每个订阅都尽量像 Claude、腾讯视频那样，从服务自己的数据里知道「上次使用」，而不是只看浏览器访问记录。

## 基本规则

**「最近使用」只采信服务官方给出的时间；拿不到，就归为 E 类，按浏览器访问判断。**

- 官方时间：服务自己的接口或页面里写明的观看 / 使用时间（具体时刻或日期）。
- 不做推断：例如比对「最近列表前后有没有变化」来猜用户用没用，这类做法一律不用。读到了记录但里面没有时间，也按 E 类处理（v2.28.1 起代码已按此执行：`SubLib.hasWatchTime`）。
- **「常见服务」里只放已经一一适配并实测过的服务**（v2.30.0 起）。没适配的不出现在目录里，用户需要时可以手动添加网址（按浏览器访问）。
- 对话类服务只读对话 ID 和时间，不读对话标题和内容。
- **官方记录为空 = 按闲置算**（v2.34.0）：接口正常回应但一条记录都没有（从没用过 / 记录范围内没用过），记成「90 天+未使用」；以前读到过使用时间就沿用那个时间。前提是账户页确认已登录，否则仍按读取失败处理（有的接口没登录也回空结果）。Claude / ChatGPT 对话列表为空同样处理。
- **会话 / 设备列表不算使用时间**：例如 Cursor 的 Active Sessions 只有「创建时间」（= 登录时间），而且插件打开后台读套餐时自己就会新建一条网页会话，不能用。

### 实测记录

- Gemini（v2.31.0）：在用户的 Chrome 里读到 1 个对话，时间 2025-12-21。
- Perplexity（v2.32.0）：读到 1 个线程，时间与网页显示一致。接口时间不带时区，按 UTC 处理（`tsUtc`）。
- Microsoft Copilot（v2.33.0）：copilot.microsoft.com 会跳到 copilot.com。「所有聊天」页同一个地址带 `Accept: application/json` 时返回 `store.chatLandingPageHistoryList.chats`，每条有 `conversationId / createTimeUtc / updateTimeUtc`（毫秒）。实测读到 1 个对话，时间对得上。套餐页免费账号只显示「Microsoft 免费服务」（另有「首月使用免费」推广位，已确认不会误判）；Copilot Pro / Microsoft 365 个人版 / 家庭版的页面文字还没用付费账号实测。
- Cursor（v2.34.0，`verified: false`）：接口地址、请求格式、空结果（返回 `{}`）、套餐接口 `membershipType: "free"` 都已实测。用户账号没有任何使用记录，**有记录时的字段**（`usageEventsDisplay[].timestamp`，毫秒字符串）是按 Cursor 后台的已知返回格式写的，配了候选字段。等有真实记录时用 Alt+检查核对，确认后改成 `verified: true`，并从 `test_extract.js` 的 `PENDING_VERIFY` 里去掉。界面显示「按使用记录」（`kind: "usage"`）。

## 结论：每个服务要单独「适配」，但不单独「写代码」

每家把「最近用过」放的位置都不一样，所以每个服务都要实地调研一次：用开发者工具找到带时间的接口。找到之后套用现成的**读取模板**，写一份配置就行。长期成本主要在维护：网站改版后读法会失效。读不到时会标记信号中断、不误报闲置，后面还要补一个定期自检。

## 级别与读取模板（`activity.js` + `background.js`）

| 级别 | 含义 | 模板 | 现有例子 |
|---|---|---|---|
| A | 官方接口给出具体观看 / 使用时间 | `api`（在服务页面里请求它的接口，支持 GET / POST，请求体可写 `{{now}}` / `{{daysAgo:N}}` 日期占位，`emptyIfNoList` 把 `{}` 当空列表）、`googleRpc`（Google batchexecute）、`tencent`（截获页面自己请求的接口）、`llm`（对话列表 + 套餐 + 额度） | B站、Perplexity、Copilot、Gemini、腾讯视频、Claude、ChatGPT |
| B | 官方页面写明观看日期（精确到天） | `youtube`（页面数据的日期分组） | YouTube |
| E | 拿不到官方时间 | 按浏览器访问判断，界面写明原因 | 百度网盘、VPN、密码管理器 |

**当前阶段只做 A、B，先做 AI 类。** 对话类服务在配置里加 `kind: "chat"`，弹窗显示「按对话记录」，不显示片名和观看记录链接。

D 类（账户页「最后活动 / 设备最近使用」）暂缓。原因：大多数服务的设备或会话列表记录的是登录 / 会话刷新时间，不等于真实使用。

### `api` 模板配置格式

```js
someService: {
  name: "Some Service",
  domain: "example.com",
  activityUrl: "https://www.example.com/history",   // 在这个页面里请求接口（带登录 Cookie）
  strategy: "api",
  kind: "chat",                                       // 可选：对话类服务
  api: {
    urls: ["https://api.example.com/v1/history?limit=30"],   // 依次尝试
    method: "POST", body: { limit: 20 },                   // 可选：POST + JSON
    list: ["data.items", "data"],                          // 条目数组的位置（候选）
    id: ["videoId", "id"],                                 // 条目 ID 字段（候选，支持 a.b.c）
    idPattern: "",                                         // 可选：从 ID 里再取一段
    ts: ["lastPlayedAt", "updated_at"],                    // 观看时间：秒、毫秒、ISO 字符串都行（必填）
    tsUtc: true,                                           // 可选：不带时区的 ISO 时间按 UTC
    title: ["title", "name"],                              // 对话类不要填
    codePath: "code", okCodes: [0], loggedOutCodes: [401], loggedOutText: "login",
    historyOffText: "history is (off|paused)",
    fallbackLink: { pattern: "/watch/(\\w+)" }             // 可选：接口不通时读页面链接（只用于诊断，不算时间）
  },
  verified: false,
  note: "…"
}
```

`test_activity.js` 会对目录里每份 `api` 配置做格式自检（`ActivityLib.validateApiSpec`），漏写字段时测试会失败。

## 加一个新服务的流程

1. 在浏览器里登录该服务，打开它的历史 / 最近记录页，开发者工具 → Network → Fetch/XHR，找到返回列表的请求，记下请求地址和返回的字段。
2. 判断级别：条目里有时间字段 → A；页面上写着日期 → B；都没有 → E，不接入读取。
3. 在 `catalog.js` 加服务（账户页地址、套餐规则，有使用时间的加 `activity: "<key>"`）；在 `background.js` 的 `CATALOG` 加读取配置。
4. 在 `test_activity.js` / `test_catalog.js` 用真实字段结构写用例。
5. 按住 Alt 点「检查」看诊断，确认最近一次使用的时间对得上，再把 `verified` 改成 `true`。

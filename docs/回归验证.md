## 自动测试基线

环境：Node.js `v24.14.1`，DOM 测试依赖 `jsdom@26.1.0`。基准包含 15 个脚本、534 个检查项。用例数量可随合理增补变化；不能通过删除原断言或跳过用例维持通过。

仓库目前没有统一测试入口和依赖清单。本次保持业务代码与测试结构不变，使用以下可复现命令。依赖安装在临时目录，不写入插件目录；临时目录清理后重新执行安装步骤。

```sh
# 在项目根目录执行；安装测试依赖，不连接产品后端。
test_deps_dir=$(mktemp -d /tmp/sub-monitor-test-deps.XXXXXX)
npm install --prefix "$test_deps_dir" jsdom@26.1.0 --ignore-scripts --no-audit --no-fund
export NODE_PATH="$test_deps_dir/node_modules"
node -e 'console.log(require.resolve("jsdom"))'
```

确认安装及依赖检查成功后执行完整测试，禁止在依赖缺失时把部分跳过算作全通过：

```sh
(
  unset E2E
  node -e 'require("jsdom")' || exit 1
  test_failed=0
  for test_file in test_*.js; do
    node "$test_file" || test_failed=1
  done
  exit "$test_failed"
)
```

语法检查另行执行；后续若新增子目录中的 JavaScript，必须纳入检查范围：

```sh
(
  syntax_failed=0
  for source_file in *.js; do
    node --check "$source_file" || syntax_failed=1
  done
  exit "$syntax_failed"
)
```

保存退出码和失败日志，查看是否出现跳过提示；不能只看最后一个脚本的输出。`test_auth_bg.js`、`test_sync_bg.js` 在有 `E2E` 时会访问实际后端，完整回归默认明确移除该变量。

## 已知缺陷与待补覆盖

已有测试全通过不代表下列问题已修复。它们已在代码导览中记录，本次准备不改变其行为：

- **混合币种闲置金额**：`$20` 与 `¥30` 的闲置价格被相加成 50，再套第一种币种。修改费用相关功能时，为按币种分别统计的正确预期先建立失败用例，不能把错误总额写成长期回归标准。
- **AI 部分接口失败**：会话/套餐成功但对话接口 500 时，当前可能以空时间列表给出退订建议。修改 AI 读取或建议时，区分接口成功且空列表、请求失败、字段缺失、部分结果；先复现再修复。
- **并发写回覆盖**：现有编辑保护测试不足以证明价格、币种、lastUsed 等所有字段安全。触及 `REFRESH_FIELDS`、存储锁或同步时，补充检查期间编辑价格、发生真实访问、删除订阅和同步更新等交错用例。
- **真实服务可用性**：目录配置、Chrome 授权与第三方内部接口不由本地模拟测试保证。新增或修改读取器需保留真实读取的验证结果和日期。
